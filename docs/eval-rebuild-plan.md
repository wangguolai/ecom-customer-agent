## 二、负样本策略（A）及其推论

**决策**：维持 README 已定调的「召回优先、拒答兜底」。超知识库 query 软推最相似商品 = **正确行为**（客服场景拒答=丢单）。

推论：
1. **TODO 里「活体昆虫 → 修成 rerank<0.55 判双低拒答」不做**——这是**开倒车**：`RERANK_SCORE_THRESHOLD=0.6` 的 rerank 绝对阈值已于 2026-08-20 被推翻（口语 query 分数整体贴 0.5，12 条全被误杀成空返回，完整链路比单路还差），现行策略是召回层双低拒答 `VEC_SCORE_LOW=0.4`。把 0.6 改成 0.55 病根不变。活体昆虫的 rerank 分（0.50）改为**观测值**，不设通过判据。
2. **负样本不进 fix 池**。理由：A 策略下负样本的「正确」不是「返回空」，而是「不许推出明显错误的东西」——这个判据无法用现有 `recalled >= min(len(expected),3)` 表达（expected 为空）。
3. **G5 负样本降级为指标观测**：在 EVAL_SET 里保留（测空返回率 + 记录 top1），但不参与通过/失败判定、不回流、不毕业。
4. **「手机壳」lock 保留但重写锁定理由**：v1 锁的对象 `宠物航空箱` 已不存在，语义从「锁用品软推」变成「锁某款粮软推」，理由需重写（否则锁的是偶然结果）。

## 五、标注原则（v2 修正）

1. **expected 必须与入库 title 严格一致**（`_validate_expected` 会校验）。
2. **expected 写全业务正确答案**（v1 此条写错）。闸门 `min(len(expected),3)` 封顶，写多不放松判定；但 Recall 指标分母是 `len(expected)`，写全会让数值下降——这是**口径不自洽**。
   → **建议同步把 `eval_retrieval.py:122` 的 Recall 分母改为 `min(len(expected), 3)`**，与闸门同口径（呼应 TODO 既有认知「回流/毕业必须同口径」）。
3. **新增强制自检：`detect_category` 与 expected 类别一致性断言**。
   根因（B1 实测）：`detect_category("皇家牌泌尿道处方粮") → 狗粮`，因 `category_synonyms.md` 狗粮行含「处方粮」。该 query 的 expected 含猫粮商品 → 被预过滤滤掉 → Recall 恒 ≤1/2 **且不报警**（静默失败）。
   自检脚本：对每条 case 打印 `detect_category(query)` 与各 expected 在 `products.md` 的类别，冲突即报错。**这是防同类坑复发的唯一手段**。
4. **避开 title 格式噪声商品**：`&amp;`(P103/P114)、含空格(P106)、半角括号(P031/P086/P073)。这些会让「用户输入 ≠ 标注」。
5. **标注写业务正确答案，不迁就当前召回**。能不能召回由评测暴露。

**回归逻辑必须改（v1 诊断修正）**：

`eval_retrieval.py:173-191` 的 `_run_regression` 对 fix 型判 `recalled >= recall_cap`。当 `expected=[]`：
```
recall_cap = min(0,3) = 0
recalled  = 0
0 >= 0  →  恒真  →  passed.add(query)  →  regression.graduate() 直接毕业
```
**这不是「判不了」，是「假阳性毕业」** —— 负样本一旦入池，第一次跑就毕业消失。

A 策略下处置：
1. **负样本不入池**（治本）。`_run_regression` 加显式分支：`if not expected: 只打印观测，不进 passed`。
2. `run_eval` 同步：负样本已 `continue`（`:95`），保持，但打印 top1 rerank 分供观测。
3. **`first_actual` 靠重跑写回**，不人工编造。

## 🔴 重大发现：混合检索在新库上**不如纯向量**

旧库：混合 0.9667 **反超**纯向量 0.92。
新库：混合 0.6639 **低于**纯向量 0.7139（差 5 个点）。

**逐层二分定位（全部实测，非推测）**：

| 实验 | 结果 | 结论 |
|------|------|------|
| 纯向量 无预过滤 vs 带预过滤 | 0.7139 = 0.7139，零 case 被拉低 | **预过滤无罪** |
| RRF（向量+BM25，无 rerank） | **0.4917** | BM25 把融合结果拖下水（比纯向量掉 22 点） |
| RRF + Rerank | 0.6639 | rerank 救回 17 点，但救不回全部 |
| RERANK_CANDIDATE_N 扫描 | N=5→0.6194、**N=10→0.6639**、N=15/20/30/50→0.6583 | **N=10 已是新库最优**，N 不是问题 |

**根因**：BM25 在新库上退化到 0.4472（旧库显著更高）。新商品标题长且高度相似
（101 个皇家商品命名模式雷同、含 `1.5kg/10kg` 之类规格噪声），关键词区分度低。
BM25 一弱，**RRF 的对称融合 `1/(k+rank_vec) + 1/(k+rank_bm25)` 就把噪声等权引入**，
挤掉向量侧的正确候选；rerank 只能从被污染的候选集里重排，救不完全。
