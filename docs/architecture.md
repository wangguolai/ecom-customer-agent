# 电商客服 Agent 架构图

> 系统设计主线。分层架构 + 数据流 + 选型理由。用。

## 1. 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│                      用户问题（自然语言）                      │
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              AgentSession（多轮会话）                          │
│   维护历史 messages（全量保留）+ 滑动窗口（token 预算+轮次切）    │
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              ReAct 循环（手写，不套框架）                       │
│   LLM 决策 → 工具调度 → 结果回灌 → 再决策（max 8 步）           │
│   防御：幻觉校验 / 死循环检测 / 参数校验 / Token 截断            │
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                   工具层（6 个工具，Function Calling）           │
│  search_products │ search_orders │ search_logistics           │
│  check_stock     │ get_return_policy │ transfer_to_human      │
└───────┬──────────────────────────────┬───────────────────────┘
        │（商品咨询）                    │（订单/物流/库存/转人工）
        ↓                              ↓
┌───────────────────┐          ┌───────────────────┐
│    RAG 检索        │          │    mock 数据       │
│  BGE embedding    │          │  订单/物流/库存     │
│  → Qdrant 向量库  │          │  （内存硬编码）      │
└─────────┬─────────┘          └───────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│                      基础设施层                                │
│   DeepSeek（LLM） │ BGE-small-zh（embedding） │ Qdrant（向量库）│
└─────────────────────────────────────────────────────────────┘
```

## 2. 数据流（一句话）

用户问题 → AgentSession 追加历史 → ReAct 循环让 LLM 输出 `tool_calls`（JSON 指令）→ 代码执行对应工具（商品咨询走 RAG，订单物流走 mock）→ 结果回灌 → LLM 再决策 → 最终答案。

## 3. 选型理由（必问「为什么这么选」）

| 决策点 | 选择 | 为什么 |
|--------|------|--------|
| LLM | DeepSeek（deepseek-chat） | 便宜 + 中文好 + OpenAI 兼容（原生支持 Function Calling） |
| Agent 编排 | **手写 ReAct 循环**，不套 LangGraph/LangChain | 理解底层「LLM 只输出指令、代码才执行」，要说明循环；框架封装了循环反而盖住要点 |
| 工具交互 | Function Calling（不手写正则 ReAct） | API 契约保证格式可靠，避免「正则解析 Thought:/Action:」的格式地狱 |
| RAG 角色 | 包装成 `search_products` 工具，和其他工具平级 | RAG 在 agent 里就是一个查询工具，路由交给 ReAct 自动选，不用写 if-else |
| Embedding | BGE-small-zh-v1.5（512 维） | 中文优化 + 本地免费（零 API 成本）+ 数据量小 512 维够用 |
| 向量库 | Qdrant 本地文件模式 | 无需 Docker（中国大陆网络限制）+ API 简洁 + 数据量小本地够用 |
| 检索策略 | 单向量检索（COSINE）+ 分层阈值 | 最小可用；混合检索（BM25+向量）+ Rerank 是下一步（README  硬项） |
| 动态数据 | 价格/库存走工具实时查，不写进向量库 | 数据分治：向量库是「快照」，动态数据走工具才有时效性 |
| 多轮记忆 | 全量保留 + 滑动窗口（token 预算 + 轮次切） | 先正确后优化：先全量保证对，再针对性截断；固定的是 token 预算不是轮次 |
| 防御 | 白名单 + 步数上限 + 截断 + 数据/指令分离 | 五类坑的「层层兜底」，不追求「一次保证 LLM 走对」 |

## 4. 当前状态与不足（「诚实讲不足」用）

- 工具全是 mock（无真实数据源）——「真实工具」验收未达，后面接真实 API 或自建后端
- RAG 只有单向量检索，还没上混合检索 + Rerank
- Prompt Injection 只做了 prompt 级缓解，代码级门槛（写操作权限开关）待做
- 无可观测性（Trace/指标）、无评测体系（这是  线）
